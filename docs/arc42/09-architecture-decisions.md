# 9. Архитектурные решения

Раздел фиксирует значимые архитектурные решения, принятые при переводе wb-rules с Duktape 1.0.2
на QuickJS (ветка `quickjs-core`, август 2026). Решения этапа TypeScript (ADR-010…016)
добавляются вместе с PR #224. Каждое решение оформлено как отдельная запись ADR
(Architecture Decision Record) в каталоге `adr/`.

## Как читать

- ADR нумеруются сквозным образом и не переиспользуются. Порядок — примерно хронологический и
  тематический: движок (001–004), промисы и асинхронность (005–007), защитные механизмы (008–009);
  решения по TypeScript (010–014) и редактору homeui (015–016) приходят с PR #224.
- Формат каждой записи: **Статус**, **Дата**, **Контекст** (почему вопрос встал), **Решение**
  (что сделано, с идентификаторами кода), **Рассмотренные альтернативы** (таблица «альтернатива —
  почему отклонена», с цифрами, где они были), **Последствия** (плюсы, минусы, риски, долги),
  **Ссылки** (файлы, PR, документы).
- Статусы: *Предложено* — обсуждено, не реализовано; *Принято* — решение зафиксировано, реализация
  частична или идёт; *Принято, реализовано* — код в ветках `quickjs-core`/`quickjs-ts` (или в master
  для #225, wbgo-private#100).
- Цифры производительности — из измерений на WB8 (arm64, 2026-08-13, см. ADR-001) и бенчмарка
  изоляции 2026-08-11 (x86-64); источники указаны в каждом ADR.
- ADR ссылаются друг на друга там, где одно решение вытекает из другого (например, ADR-004 →
  ADR-008).

## Что сознательно не решено (roadmap)

Ряд вопросов обсуждался, но решение отложено; они не имеют ADR и перечислены здесь, чтобы
не создавать ложного впечатления о принятых обязательствах:

- **ES-модули (`import`/`export`) в файлах правил.** Сейчас файл — CommonJS-подобная
  async-обёртка (ADR-006), модули — `require()` с кэшем per-realm (ADR-003). Переход на
  ES-модули требует собственного загрузчика, политики совместимости с `require` и `module.static`,
  решения о `module.exports` после TLA. Ожидает отдельного рассмотрения.
- **Трассировка и симуляция правил** («что сработает, если контрол X изменится», запись/воспроизведение
  событий). Данные для этого есть (DepTracker, `LocFileEntry`, лог `/wbrules/log/*`), но ни формат,
  ни интерфейс не выбраны.
- **Per-file лимиты памяти/времени.** Невозможны в модели одного heap (ADR-004); альтернативная
  модель (runtime на файл или процесс на файл) не принята и не отвергнута окончательно — текущие
  guardrails (ADR-008) признаны достаточными.
- **Форк `wirenboard/quickjs`** (ADR-002) — создаётся только при появлении первого патча.

- **Секреты в файлах правил** (telegram-токены, chat_id, пароли) попадают в `Editor.Load`, трейсбеки и консоль; Маскирование в консоли и API секретов — в roadmap.

Открытые риски и технический долг, вытекающие из принятых решений, перечислены в разделе «Риски и технический долг» каждого ADR.
