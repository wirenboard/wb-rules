# Архитектурная документация wb-rules (arc42)

Документация по архитектуре **wb-rules** — движка правил автоматизации контроллеров
Wiren Board (Go-процесс со встроенным QuickJS через шим `internal/quickjsduk`). Структура следует шаблону
[arc42](https://arc42.org/): 12 разделов плюс журнал архитектурных решений (ADR).

## Что описывает и какой статус

Документ фиксирует состояние **ветки `quickjs-core`** на **август 2026** — этап замены
движка Duktape 1.0.2 на QuickJS. Подразделы о TypeScript и редакторе (ADR-010…016,
соответствующие части глав) добавляются вместе с PR #224:

| Репозиторий | Ветка / PR | Содержание |
|---|---|---|
| `wirenboard/wb-rules` | `quickjs-core` → `master`, PR [#223](https://github.com/wirenboard/wb-rules/pull/223) | движок QuickJS, шим, промисы, TLA, async-библиотека, guardrails, корпус |
| `wirenboard/wb-rules` | `quickjs-ts` → `quickjs-core`, PR [#224](https://github.com/wirenboard/wb-rules/pull/224) | TypeScript: `tsgo`, фоновая проверка, `types/wb-rules.d.ts`, реестр `WbControls` |
| `wirenboard/homeui` | `rules-editor-typescript`, PR [#1202](https://github.com/wirenboard/homeui/pull/1202) | языковой сервис TS в браузере, диагностики контроллера, UX ошибок |
| `wirenboard/wb-tsgo` | `main` | сборка немодифицированного typescript-go в deb-пакет `wb-tsgo` |
| `wirenboard/wbgo-private` | PR #100 (смёржен) | фикс гонки драйвера при быстрых сохранениях (`wbgo.so`) |

Ранние сборки поставляются через testing set `quickjs-typescript`. При расхождении
документа с кодом первичен код; при слиянии PR документ нужно сверить с `master`
(риски — в ADR).

## Как поддерживать

- **Когда писать ADR.** Любое решение, которое трудно отменить или которое меняет
  контракт: смена движка/зависимости (`third_party/quickjs`), изменение
  поверхности шима (`internal/quickjsduk`, «заморожена»),
  протокола Editor RPC, семантики ошибок (лог vs throw), лимитов
  по умолчанию, модели изоляции. Небольшие фичи в `lib.js` ADR не требуют — достаточно
  changelog и README.
- **Формат ADR** (см. `adr/ADR-001-*.md`): заголовок `ADR-NNN: <решение>`, поля
  «Статус» (Предложено / Принято / Реализовано / Отменено, с заменяющим ADR), «Дата»,
  разделы «Контекст», «Решение», «Рассмотренные альтернативы», «Последствия и риски»,
  «Источники». Нумерация сквозная, старые ADR не редактируются — пишется новый со ссылкой.
- **Когда обновлять разделы.** §5–§8 — при изменении структуры пакетов или сценариев;
  §10 — при новых измерениях (указывать дату, устройство, версию); «Риски и технический долг» в ADR — закрытый риск
  помечать «закрыто» со ссылкой на PR, а не удалять; §12 — при появлении нового термина
  в коде или README.
- **Язык.** Документация arc42 — на русском; идентификаторы, пути и сообщения лога —
  как в коде; комментарии в коде — на английском (см. §2).
