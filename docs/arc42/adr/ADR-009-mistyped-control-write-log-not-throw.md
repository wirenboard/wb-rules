# ADR-009: Неверно типизированная запись в контрол — лог с file:line, а не исключение (#225)

**Статус:** Принято, реализовано (в master с 2.46.4)
**Дата:** 2026-08-18

## Контекст

`getControl("dev/ctrl").setValue("123")` на контроле типа `value` молча не срабатывал:
драйвер отклонял запись, отказ уходил через `wbgong.Error.Printf` в journal, а в консоли правил
homeui — там, где автор правила ищет причину, — ничего не появлялось. Вдобавок отклонённая запись
всё равно обновляла кэш значения в `ControlProxy`, и все читатели видели несуществующее значение.
Проблема существует с 2015 г. и не зависит от движка, поэтому исправление нужно и в master
(Duktape, 2.46.x), и в ветке QuickJS. Выбор стоял между исключением в JS и видимым сообщением об
ошибке без изменения потока управления.

## Решение

- `ControlProxy.SetValueAt` при отказе драйвера пишет
  `control X/Y: write ignored (...) at /etc/wb-rules/foo.js:14` через `engine.Log(ENGINE_LOG_ERROR)`
  → топик `/wbrules/log/error` (консоль отладки homeui), **не бросает** исключение.
- Кэш значения не «отравляется»: `updateValueHandler` срабатывает только при `err == nil`.
- Call-site (`file:line`) вычисляется лениво из JS-стека; редактор homeui показывает такие
  строки как lint-диагностики у строки (ADR-016).
- Изменение сделано отдельным PR в master (2.46.x, Duktape), а не только в ветке QuickJS — баг не
  зависит от движка.

## Рассмотренные альтернативы

| Альтернатива | Почему отклонена |
|---|---|
| Бросать catchable-ошибку в JS | влияние на корпус ≈ 0, но ломает семантику «swallow-and-log», действующую с 2015 г.: правила без `try/catch` начали бы прерываться на полпути — недопустимое изменение поведения для bugfix-релиза |
| Оставить только syslog (`wbgong.Error.Printf`) | невидимо в UI; для пользователя равносильно молчанию |
| Warning вместо error | запись данных не произошла — это ошибка правила, уровень `error` корректен |

## Последствия

Плюсы:
- Обратная совместимость поведения сохранена; проблема видна там, где пользователь её ищет
  (консоль правил, редактор).
- Исправлено отравление кэша — оно влияло на всех читателей контрола.

Минусы и риски:
- Ошибка не останавливает правило; код после неверной записи выполняется с ложным
  предположением об успехе.
- Статическая защита — через реестр типов контролов в TS (ADR-014): `dev["buzzer/enabled"] = 123`
  ловится чекером до исполнения.
