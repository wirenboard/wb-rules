# ADR-001: QuickJS вместо Duktape 1.0.2 как встраиваемый движок правил

**Статус:** Принято, реализовано
**Дата:** 2026-08-11 (бенчмарк изоляции), 2026-08-12 (решение о переходе на QuickJS)

## Контекст

wb-rules исполнял правила на Duktape 1.0.2 (2014 г.): только ES5, нет промисов, `Proxy`
доступен лишь через форк, компьютерно-тяжёлый код примерно в 4 раза медленнее современных
интерпретаторов. Целевые устройства — Wiren Board 6/7 (armhf) и Wiren Board 8 (arm64) с
ограниченной RAM и флешем. Исходный вопрос был шире, чем «сменить движок»: измерить стоимость
*изолированного* исполнения множества скриптов на встраиваемом Linux и выбрать модель рантайма.

Бенчмарк маржинальной RAM на один изолированный скрипт (workload `rules`, наклон МНК по RSS/PSS,
прогон 2026-08-11, Debian 13 x86-64):

| Вариант | MB/скрипт | База процесса |
|---|---|---|
| quickjs-context (realm в общем runtime) | 0.17 | 1.8 MB |
| quickjs-runtime (отдельный runtime) | 0.20 | 1.8 MB |
| bun-vm-context | 0.21 | 44.5 MB |
| duktape-heap | 0.26 | — |
| node-vm-context | 0.29 | 46.6 MB |
| deno-vm-context | 0.33 | — |
| qjs-proc (процесс на скрипт, PSS) | 0.48 | — |
| node isolated-vm | 1.29 | 49.9 MB |
| bun-workers | 2.65 | 40 MB |
| bun-proc / deno-workers | 7.19 / 8.09 | — |
| node-proc / node-workers / deno-proc | 9.98 / 10.31 / 12.42 | 47 MB |

Холодный старт `qjs` 3.5 мс против 31 мс у Node; занимаемый диск ~1 MB против 89–120 MB.
Для 16 скриптов: QuickJS ≈ 5.9 MB суммарно, Node workers ≈ 215 MB.

## Решение

Заменить Duktape 1.0.2 на QuickJS, сохранив модель «движок внутри Go-процесса wb-rules»
(один процесс, один JS-поток, см. [ADR-004](ADR-004-one-runtime-realm-per-file.md)). Язык правил становится полным ES2025 плюс
6 из 7 фич ES2026 (нет `Array.fromAsync`).

## Рассмотренные альтернативы

| Альтернатива | Почему отклонена |
|---|---|
| Node/Deno/Bun Workers | 8–10 MB/скрипт + 40–47 MB базы; Bun дешевле (2.65 MB), но нет armhf-сборки (установщик знает только linux-x64/aarch64), `resourceLimits` в Bun — заглушка `{}` (проверено по исходникам), `smol:true` ничего не меняет (2.62 vs 2.65 MB); Deno — только aarch64 |
| `node:vm` контексты | 0.29 MB, но «not a security boundary», нет per-script лимитов, пустой realm без `require`; если давать скриптам npm-пакеты — только workers/процессы (10+ MB/скрипт) |
| Node + `isolated-vm` | 1.3 MB и реальные лимиты, но тянет Node-рантайм (~50 MB базы, 89+ MB флеша) |
| Процесс на скрипт (`qjs-proc`) | 0.48 MB PSS, «kernel-grade isolation», но разрушает общий heap (`module.static`, `dev`, общий драйвер) и усложняет IPC; не выбран |
| goja (интерпретатор на чистом Go, без cgo) | в бенчмарк не включался и всерьёз не рассматривался: не даёт realm-семантики Duktape-шима ([ADR-003](ADR-003-go-duktape-compatible-shim.md)) и не имеет замеров RAM/скорости на целевых платформах; решение принималось между встраиваемым C-движком и JS-рантаймами |
| Остаться на Duktape / перейти на Duktape 2.x | отдельно не рассматривалось; мотивация ухода — ES5 2014 г., нет промисов, 4× медленнее |

Вывод по npm: пакеты остаются на стороне хоста (Go), скрипты получают курируемый API — как
wb-rules и делал прежде.

## Последствия

Плюсы:
- Современный язык (промисы, `async/await`, `let/const`, стрелки, классы, `Proxy` штатно).
- На WB8 (arm64, тот же набор правил): RSS 37.6 → 36.7 MB, PSS 36.1 → 35.3 MB;
  ES5 compute-бенчмарк 1300 → 310 мс (4.2×).
- Встраиваемость: ~1 MB кода, C без зависимостей, кросс-сборка штатным cgo ([ADR-002](ADR-002-bellard-quickjs-submodule.md)).

Минусы и риски:
- Медиана реакции на MQTT 6.98 → 7.61 мс, p99 12.3 → 14.7 мс — накладные расходы шима ([ADR-003](ADR-003-go-duktape-compatible-shim.md)); для MQTT-bound правил несущественно.
- Интерпретатор без JIT — нерелевантно для данного класса нагрузки.
- Однопоточная модель сохраняется: один зависший синхронный цикл блокирует все правила — отсюда guardrails ([ADR-008](ADR-008-guardrails-watchdog-heap-loadguard.md)).
- Переход вынуждает решить вопросы промисов/event-loop, которых в Duktape не было ([ADR-005](ADR-005-microtask-pump-rejection-tracker.md), [ADR-006](ADR-006-top-level-await.md), [ADR-007](ADR-007-promise-native-lib-js.md)).

### Риски и технический долг

- Документация: вводная README переписана под современный язык (ES2025+, промисы, top-level `await`), legacy-идиомы ES5 вынесены в одну заметку (2026-08-19); примеры в справочных разделах API местами по-прежнему на `var`/`function` — они работают как есть и переписываются по мере правок.
